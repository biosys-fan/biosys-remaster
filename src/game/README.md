# src/game: the port of BiosGame.dll

Namespace `biosys::game`. Rules: `WORKERS.md` ("Game logic"). Reference: `analysis/notes/saveblob.md`.

shows 1444 of 1444 items typed and 0 raw bytes.

`SaveGame` builds the world first (`buildWorld`, a replay of the original start-up code, constructor by
constructor, in the original order) and `load` then hands each saved slot to the live item at the same
list position, exactly as `CWorld::Load` does; `self.resolve(world)` at the end turns the saved names of the player
into pointers (the end of `CSelf::Load`). `Item::className()` is the class the code builds (what `items`, `dump` and
`ctors` print); the generator's save-format names only serve for constructors no class registered (`CObject`, not
`CMiscObject`: dll:10028c20 is the CObject constructor).

## Game state (no globals)
`World::state()` is the one `GameState` of a world: `rng`, `lightsOn` (DAT_100c3224, written into every site slot),
`features` (DAT_1009f424 pod global, DAT_100c42cc seal global, DAT_100c1e24 current site name, `_DAT_100c4274` data
terminal, DAT_100c1150..1160 fuse boxes), `ocean` (DAT_100c1cc8), `message` / `log` (what the `CWorld::Find*`
functions and the constructors write to the global text buffer DAT_100c2650 / Eng_WriteLog) and
`fixes` (the remaster switch, below). Two `SaveGame`s in one process share nothing (`biosys-gametest worlds`). The only
process-wide data left in `src/game` are the constructor factory slots (`ctorSlot_<addr>()`), which are registered
once at start-up and never change afterwards.

## Look-up functions
One implementation each, on `World`, translated from the original: `findBiomeCel` (dll:10013ad0), `findWaterTank`
(10013f80), `findSite` (100139b0), `findFeature` (100147c0), `findObject` (100145a0), `findPlant` (FUN_10014400),
`findPage` (FUN_10013850). They return typed pointers and, like the original, **log and return NULL**: the text
("BiosGame.dll: Unrecognised site - NAME") is left in `state().message` and appended to `state().log`. Callers that only
store the pointer keep the null (as the original does); callers that dereference it in the original (flow and ocean
constructors, the builders: "log, `delete this`" / crash) use `requireBiomeCel/WaterTank/Site/Feature`, which throw
`biosys::Error`.

## How to port a class (the recipe)
1. Pick the class's constructor(s) in `build/biosys-gametest ctors` (address, signature letters) and read the
   typed declaration in `world_ctors.gen.h` (`CtorFn_<addr>`: the exact C++ signature the builder calls).
2. Write `src/game/<class>.h/.cpp` with `class X final : public Item`. Members go in the class, named after
   the original (`analysis/notes/*.md`); pass `(ctorAddr, "CClass", name)` to `Item`. Override `typed()` to
   return true.
3. `saveSlot(SlotWriter&)`: write the members in saveblob.md slot order (`writeF64`, `writeI32`, `writeStr`...).
   `loadSlot(SlotReader&)`: read them in the same order with their member names (`readF64("m_dOxygen")`);
   the names are what `dump` prints. Unwritten members: `readZeros("name", n)`; end with `r.finishPad()`
   (the rest of the slot must be zero). Put `// dll:ADDR` on both functions.
4. Register the constructor in the same `.cpp`, one line per constructor address:
   `BIOSYS_REGISTER_CTOR(1000ec80, [](World& w, const char* name, int32_t a1, double a2, ...) -> Item* { return w.adopt(std::make_unique<X>(name, ...)); });`
   The lambda must match `CtorFn_1000ec80` exactly (a mismatch is a compile error). Item arguments arrive as `Item*`:
   convert them with `&as<CBiomeCel>(a)` and keep the concrete type in the class.
5. Test: `make && bash tests/test_game.sh`. The round trip must stay identical and the dump check compares
   every typed item with `analysis/scripts/biosys_savblob.py dump` automatically. Do not edit generated files; if a
   constructor argument is typed wrongly, add an entry to `ARG_OVERRIDES` in `tools/gen/gen_world.py` and rerun
   `python3 -I tools/gen/gen_world.py`.

A class with extra typed constructor state that the blob does not carry (`CBiomeCel` tanks, site cel, ...)
receives it through the factory arguments: `Item*` arguments are earlier items of the same build, `Biome*` the static
biome object, `DllPtr` a pointer to DLL data.

## Random numbers
`Rng` (`rng.h`) is the MSVC 4.2 runtime generator: `seed = seed * 214013 + 2531011; rand = (seed >> 16) & 0x7fff`
(`_rand` dll:10079380, `_srand` dll:10079370), initial seed 1. `randRange` (dll:100075a0), `randPlusMinus` (dll:100075d0)
and `chance` (ChancePercent dll:10007570) are built on it. The original seeds it once, with `GetTickCount()`, at the
top of `Event_OnStartup` (dll:1001d7b0); game code has no clock, so `SaveGame::Options::randSeed` (default 1)
plays that value and `SaveGame` seeds `world.state().rng` before the world is built. The generator lives in the
`GameState`; there is no global. The one use in the builders is the `CBiomeSensor` constructor (dll:1005d300): each of
its 11 first readings is the cel value plus `RandPlusMinus(error)`, drawn in the order of the original (the original adds
in x87 extended precision, the port in double). All saved games overwrite these values.

Other callers of `rand()` (not ported yet) are listed in the final report of the integration pass: `CWorld::CWorld`
(dll:10010f70) draws four `RandRange` values at static-initialisation time, i.e. from seed 1 before `srand`.

## The remaster switch (`fixes.h`)
`struct Fixes` holds one `bool` per distinct bug of the original (every `// ORIGINAL BUG` site of `src/game`); `GameState::fixes` is the
world's copy (`world().state().fixes`), all false = `faithful`, the default everywhere. Every bug site reads `if (fixes.<flag>) { intended }
else { original, unchanged }` with a one-line comment on why the intended behaviour is evident. Presets: `faithful`, `safe` (over-reads,
uninitialised data, NULL reads, the two Load-calls-Save slips), `cosmetic` (= safe + display-only), `restored` (= cosmetic + every
behaviour-affecting fix whose intent is evident). Flags whose intent is not evident (`Unclear`) are in no preset and can only be named.
`Fixes::parse("restored,-rainWashesPollution")` takes a preset or a comma list of flag names (`-name` removes). The list of flags is the
`BIOSYS_FIXES` table in `fixes.h` (name, tier, description); the evidence, addresses and measurements are in `FIXES.md`.
Setting it: `SaveGame::Options::fixes` (before the world is built), `SaveGame::setFixes`, `BiosGame::Config::fixes` / `BiosGame::setFixes`
(the front end's `--fixes` option calls these). `StoryLogic` reads `synthSoundHandleInit` once, when `BiosGame` is constructed. Tests:
`tests/test_fixes.sh` (`build/biosys-fixtest`: one check per flag; `build/biosys-fixmeasure`: the effect on the idle world,
`tests/fixmeasure_compare.py` prints the tables of FIXES.md).

## The terminal's own switch (`src/engine/bs4fixes.h`)
The BioSys 4 terminal is engine code and cannot see `game::Fixes`, so its bugs have their own table, `Bs4Fixes` (one bool per bug, default all false =
the original), carried by `Bs4Options::fixes` / `Bs4::fixes()` and set through `Engine::setBs4Fixes`. `src/app/main.cpp` sets it: all preset flags for
`--realism corrected|closedloop`, none for `faithful`; `--fixes` takes the terminal's flag names next to the game's (the words that are no terminal flag go
on to `game::Fixes::parse`, which refuses unknown ones; `faithful|safe|cosmetic|restored` go to both). A site reads `if (owner().fixes().flag) { intended }
else { original }`. List, evidence and the checked non-bugs: FIXES.md, section "Terminal"; tests `tests/test_bs4fixes.sh`
(`build/biosys-bs4test --fixes LIST --gamefixes LIST`).

## Realism and difficulty (`settings.h`)
`struct Settings { Fixes fixes; Model model; Tuning tuning; }` is the front door (`Settings::parse(realism, difficulty, fixesOverride)`); `GameState::fixes / model / tuning` hold it, `SaveGame::Options::set`, `BiosGame::Config::set`, `setSettings` set it. `Model` is a table of named bools like `Fixes` (`BIOSYS_MODEL`: A1 proteinPerSecond, A2 savannahSoilAlarm, A3 waveMachineSetpoint, A4 deadPlantsRespire, A6 vapourFromSoil, A7 transpirationHumidifies, A11 houseEnvelopeSlow, A12 floodedPlantFormula); each site reads `if (model.<flag>) { corrected } else { original }` with a comment on the reasoning. `Tuning` is a table of doubles (`BIOSYS_TUNING`): multipliers (1 = original, the last factor of the product so that 1.0 is exact) and start values (< 0 = keep the saved value; applied only by the new-game menu command). Levels: realism `faithful` / `corrected` / `closedloop`, difficulty `guided` / `original` / `survivor`. Faithful + original is the unchanged translation. Everything (flags, knobs, calibration, measurements, deviations from the study): `SETTINGS.md`. Tests: `tests/test_settings.sh` (`build/biosys-settingstest`, `build/biosys-settingsmeasure`).

## Options of the save container
`SaveGame::Options`:
* `fixes` (default faithful): see the previous section.
* `repairOriginalLoadBugs` (default `false`; shorthand for `fixes.lungLoadBaseBlock` + `fixes.hatchLoadBaseBlock`). `CLung::Load` (dll:100102d0) and `CHatch::Load` (dll:1001ce10) call
  `CFeature::Save` instead of `CFeature::Load`, so the original skips the 40-byte base block of every lung and hatch in
  the saved game and keeps the live state. The port does the same by default (a loaded game then differs from the file
  in exactly those blocks; `biosys-gametest loadbugs` lists them). With `true` the block is loaded and a saved game
  round-trips byte for byte; `roundtrip` and `dump` of the test tool use it.
* `randSeed` (default 1): see above.

## Notes on the replay
* Variables of the original builders (`pCVar2`, `pvVar1`) are kept in `world_build.gen.cpp`.
* `Rel` lists are the lists besides the ten tables (pages, site feature/FX/link lists, ...); `World::related`.
* The constructors of the classes apply what the original constructor does to *other* objects: `CFood` registers its
  fruit on its plant (`CPlant::addFruit`), `CWaterPump::SetParam` stores the destination tank into its flow
  (`CWaterFlow::setTo`), `CRainMachine::Load` calls `CWorld::SetWaterFlowsSource` (`World::setWaterFlowsSource`),
  `CVidLink` saves and loads the flags that live in its `CVidMessage` objects.

## Guard against unported virtual methods

`tests/test_vtables.sh` reads the virtual tables of the original DLL (static file read) and fails when a game method in one of them is
mentioned nowhere in `src/`. It exists because three machines misbehaved for exactly that reason and nothing failed: the fuse box never
drew its fuses and lamps (`CFuseBox::Display`), the water tanks had no tap, no shower and filled no container (`CTanksCabinet` vtable
+0x30 / +0x34 / +0x3c / +0x44), a seal ignored closed media and its box picture (`CSeal` +0x60 / +0xa0), and the alarm icons of the sensor
panels played only once (`CBiomeSensor` / `COceanProbe` +0xa0). All ported on 2026-11-22. The test's two short lists name the methods that
are deliberately not ported (log dumps) or were looked at one by one. It cannot see a method that is ported wrongly; the lift's
redraw (a wrong engine call inside a ported method) was such a case.

Since 2026-11-23 this test is one part of **the audit** (`tests/audit/README.md`): `tests/test_parity.sh` compares every routine of the
original with its translation (ported at all, same picture / sound / animation names, same routines called), `tests/test_sweep.sh` enters
every page and clicks every hotspot headless and compares what happens with a record, `tests/test_visual.sh` watches the presented frames
for flicker and colour jumps. When a machine is reported as not working, run these three first; when game logic is changed on purpose,
look at the differences they print and re-record. First pass (2026-11-23) found and fixed: the game stopping when the extinguisher is
used on a fire or a fuse box (`ObjExtinguisher::peek` +0x40) and when poem1 is picked up (`GameObj` +0x2c), the cross-fades of page jumps
never running (`BiosGame::onGetCrossFadeEx`, a missing backslash), the alarm clock's font, a double drop call at the CE7 cylinder holder.
